# Clone Home -- class map (phase 1)

Renamed reference source: [`../src/`](../src/), generated by
`python tools/rename_ch.py` from [`names.map`](names.map) and compile-checked
against the MIDP/CLDC/Nokia-UI stubs (0 errors). Edit `names.map`, not `src/`.

The renaming is done on the class files' symbol tables (Vineflower's
`--user-renamer-class`, see `tools/ch_rename/ChRenamer.java`), not with regexes,
so every reference is rewritten correctly even though the obfuscator reused `a`,
`b`, `c` ... for different things in every class. Each renamed method also keeps
a `// $VF: renamed from: b (int) void` comment in `src/` giving its old name.

**Policy**: a member is renamed only when its role is confirmed from call
sites. Everything else keeps its obfuscated name and is listed under "Not yet
mapped" below. Names marked *(provisional)* are best readings, not proof.

## Engine (`a`)

* **Timing.** `frameTime` is the ms since the last frame, clamped to
  `[minFrameTime, maxFrameTime]` = `[50, 100]` (set by `Game`'s constructor, so
  the target is 20 fps). `Game.update` accumulates it and steps game logic every
  40 ms (`tickAccum`), i.e. logic runs at 25 Hz, independent of frame rate.
* **Screen.** 240x320, full screen. `setViewport(w,h)` centres a smaller canvas
  and `paintFrame` clears the borders once when it changes.
* **Keys.** `keyCodeTable` maps MIDP key codes to 30 logical key numbers:
  1=UP(-1) 2=LEFT(-3) 3='#' 4=CLEAR(-8) 5=RIGHT(-4) 6=DOWN(-2) 8=FIRE(-5)
  10='*' 16..25='0'..'9' 27=LSOFT(-6) 29=RSOFT(-7). `keysHeld` / `keysPressed` /
  `keysReleased` are bitmasks over those numbers; `pollKeys` moves the pending
  masks into them once per frame. The digit keys duplicate the d-pad (4/6/2/8/5).
* **Records.** `readRecord(id)` / `writeRecord(id, bytes)` wrap one RMS store
  per id, split into 786432-byte records. Ids 1..4 are the save slots and the
  settings record, `-9` is the sound-settings record (3 bytes, `syncSettings`).
* **Resource banks.** `selectBank` lazily opens `/RP<bank>`; `parseBank` reads
  the container (see `ASSET_FORMATS.md`). Resource id = `bank << 10 | index`.
  `loadImage` decodes a PNG resource; passing a second byte array applies the
  byte-swap palette trick (`swapPngBytes`, data in resources 1094/1095).
* **Sprites / fonts.** `loadSprites(id)` reads an atlas resource (PNG + a table
  of rectangles) into a `Sprite[]`. A `Sprite[]` installed with `setFont` is
  the bitmap font: `charCode` = glyph code, sorted, found by binary search
  (`findGlyph`); `advance` = width; entry 0/1/2's `metric` = line height /
  baseline / space width. `drawString` anchors follow MIDP (`1`=hcenter,
  `8`=right, `32`=bottom, `64`=baseline).
* **Tile map.** `initTileMap(cols, rows, sheet, tileW, tileH)`, `setTile`,
  `fillTiles`, `setScroll`, `drawTileMap`; a negative tile value indexes
  `animatedTiles` so one write animates every instance of a tile.
* **Animation player.** `loadAnimSet(id)` loads a resource of type 247;
  `startAnim(slot, animSet, sequence)` starts a sequence in a slot,
  `stepAnim(slot, dt)` advances it (returns whether it is still playing),
  `drawAnim` / `getAnimBounds` draw it or measure it against a `Sprite[]`.
  The per-sequence data is delta-coded in `loadAnimSet` (private arrays are left
  unnamed pending a proper read).

## Game (`b`): coordinates and world

* **Tiles are 57x38 px**, a section is **28x18 tiles** (1596x684 px). Positions
  are 24.8 fixed point (`>> 8` = pixels): `playerX`, `playerY`; `playerRow` =
  tile row of the feet. `playerPixelX()` / `playerPixelY()` return pixels.
* **Raw tile codes** (`getRawTile`): the level stream stores `code + 32` per byte.
  `buildSection` decodes a section into `tiles` (what the engine sees) and
  spawns things from the raw codes:

  | Code (`getRawTile`) | Meaning | Evidence |
  |---|---|---|
  | 0..25 | passable background | `isPassable` |
  | 26..31 | hazard: `health -= 4` and knock-up for the player, `health--` for an enemy standing in it | `updateEnvironment`, `Enemy.stepPhysics` |
  | 32..37 | one-way platform (passable sideways, stood on) | `isPassable`, `onOneWayTile` |
  | 38..58 | solid | `solidColumnMask` |
  | 59 | collectible, spawned only if `collectibleAvailable(worldId)` | `buildSection` |
  | 60..66 | switch: `addSwitch`; hitting it in melee clears bit (code-60) of `doorBits` | `meleeAttack` |
  | 67..70 | moving platform (`platformDir`; 2 tiles wide horizontally, 2 tall vertically) | `updatePlatforms` |
  | 71..79 | crate stacks (`placeCrate`; up to 50 crates) | `buildSection` |
  | 80..85 | invisible swingshot zone: arms `swingshotState = -1` for 10 ticks; drawn as ground variants | `updateEnvironment`, `buildSection` |
  | 86..93 | zipline endpoints; even = start, odd = end, pair = code>>1 (4 lines) | `setZiplineEndpoint` |
  | 94..100, -95 | door, blocks while its `doorBits` bit (code-94; bit 7 for -95) is set | `isPassable` |
  | 101..120 | hint trigger, id = code-101 (`hasHintFlag`, shown once) | `updateEnvironment` |
  | 121, 122 | swingshot anchor | `trySwingshot` -> `startSwingshot` |
  | 123, 124 | checkpoint: passing it sets `spawn*` | `updateEnvironment` |
  | -62..-93 | second hint range (ids 20..51, `hintFlagsHigh`) | `updateEnvironment` |
  | -105..-118, -104 | enemy spawns via `enemySpawnTable` (`eT`); -104 = code 13 | `buildSection` |
  | -119..-130 | enemy spawns via `eS` (odd codes also copy the tile to their right) | `buildSection` |
  | -101 | checkpoint pad (sets the initial spawn, sprites `checkpointSprites`) | `buildSection`, `drawTileLayer` |
  | -102, -103 | animated tile / plain tile | `buildSection` |

* **Sections.** A world (`worldId` 1..15, 16 = challenge arenas) is 2..6
  sections (`sectionCount`) of 28x18 tiles. `sectionExits[section*4 + 0..3]`
  gives the neighbour when the player walks off the up/left/right/down edge
  (`switchSection`, direction codes 1=up/6=down/2=left/5=right), `-1` = none.
  `sectionTileBase` maps a section id to its slice of `sectionTiles`; `tilesetId`
  picks the background art (`loadTileset`, resource ids `{2085,2088,2089,1062}`).
* **Player.** `airState`: -1 on ground, 0 falling, 1 jumping, 2 gliding.
  `playerAnim` (via `setPlayerAnim`): 0 idle, 1 run, 2 jump, 3 fall, 4 land,
  6 zipline, 7/8 shoot, 9 hurt, 10 dying, 11..14 melee/combo. `inputIntent`:
  1 jump, 2 left, 5 right, 8 fire. `health` 0..20. `weaponsOwned` bit i = weapon
  i (bit 0 = wrench). `currentWeapon` 0..7. Weapons level up (`weaponLevel`
  0..2) after 20 kills with them (`weaponKills`); `maxAmmoTable[w*3 + level]`.
* **Swingshot** (`swingshotState` 0..5 in `updateSwingshot`) and **zipline**
  (`updateZipline`) are the two traversal gadgets.
* **Crates** use a doubly linked stack (`crateAbove` / `crateBelow`); breaking
  one makes the ones above fall (`removeCrate`, `updateFallingCrates`).
* **Pickups** (`spawnPickup`): kind 0/1 = bolts, 2 = health (`health += 4`),
  3 = ammo (`addAmmo`). They drift toward the player (`updatePickups`).

## Game: state machine (`state`)

`state` is a `static int`; `update()` switches on it, `render` on the same.

| Value | Meaning |
|---|---|
| 0 | playing a level |
| 1 | challenge-arena selection (12 arenas, 3 pages via `dx`) |
| 2 | ending / credits (marks the game complete, `RatchetMIDlet.markGameCompleted`) |
| 3 | world map (`mapNodes`, `mapEdges`, navigation tables `navUp/Down/Left/Right`) |
| 4 | pause menu |
| 5 | sound on/off |
| 6 | load-game slot list (`drawSaveSlot`) |
| 7, 8 | quit confirmations (exit the app / return to title) |
| 9 | confirm overwrite of a used save slot |
| 10 | "game saved" |
| 11 | weapon / ammo shop (`weaponPrices`, `refillPrices`) |
| 12, 13 | shop: confirm purchase / not enough bolts |
| 14 | arena briefing (objectives `arenaHealthDrain`, `arenaNoDamage`, `arenaLimitedAmmo`) |
| 15 | arena won (reward `arenaReward[sectionId]`) |
| 16, 17, 24 | transient level-start states (17 becomes 0 next tick) |
| 18 | level results, pages 0..2 (`resultsPage`; `computeScore`) |
| 19 | arena failed (out of ammo) |
| 21 | results follow-up: save and continue / replay the level from its entry snapshot |
| 22 | weapon wheel (`weaponNext` / `weaponPrev`) |
| 23 | yes/no prompt after the first completion (leads to `startBonusMode`) *(provisional)* |
| 99..104 | boot: init, three splash screens, load, done (`loadAssetsStep` runs 17 steps, one per tick) |
| 105 | title / main menu; a second state machine, `screen` (`setScreen`, `handleScreenInput`, `renderMenuScreen`) drives its screens |

`levelStart*` fields (`levelStartBolts`, `levelStartWeapons`, ...) are a snapshot
taken by `enterLevel` and restored by state 21's "replay" option.

## Data tables the game loads (`loadGameTables`, resource 1034)

28 length-prefixed byte arrays (one length byte, then that many bytes), read in
this order: `Enemy.maxHealth`, `attackDamage`, `boltDrop`, `burstCount`
(indexed by enemy spawn code `spawnCode`), `Enemy.attackCooldown` (indexed by
enemy `type`); `Projectile.damage`, `halfWidths`, `halfHeights`, `speeds`
(indexed by shot type); `navUp`, `navDown`, `navLeft`, `navRight`, `weaponNext`,
`weaponPrev`, `collectiblesPerLevel` (the `al`..`ar` group);
`cJ` (message-page count per hint), `cL` (portrait frame per message), `nodeWorld`,
`nodeSection`, `nodeRequiredBit`, `nodeEdgeCount`, `parTimes`, `eH` (the name-entry
alphabet), `dZ` (weapon-wheel icon offsets), `eS` / `eT` (the two enemy spawn
tables) and `fireDelay`. Read with `Game.loadGameTables` (resource 1034).
Parsed independently in Python, the 28 arrays consume exactly the resource's 746
bytes. Sizes: enemy stats 30 (spawn codes 0..29) except `attackCooldown` 8 (by
`type`); shot tables 33; `nav*` 20 (world-map nodes); `weaponNext`/`weaponPrev`
8 (a ring over weapons 0..7: 0,2,3,5,1,7,4,6); `fireDelay` 8. `parTimes` values
are unsigned seconds (read with `& 255`).

`Enemy.loadStats` (resource 2049, 8 x 8 bytes) and `loadPlayerHitboxes`
(resource 2066) load hitbox tables, each value scaled by `spriteBaseHeight / 44`
(44 is the reference sprite height). Enemy and shot stats live in data, not
code, which is good news for both the port and for modding.

## Projectile types (`Projectile.type`)

Weapon `w` fires type `base + weaponLevel`: w1 -> 0..2, w2 -> 3..5 (lobbed,
gravity), w3 -> 6..8 (straight), w4 -> 9..11 (long beam, drawn as lines),
w5 -> 12..14 (chain, 3-point trail), w6 -> 15..17 (thick beam), w7 -> 18..20
(homing, `homeInOnTarget`). 21..29 are impact animations, 30 the hit spark.

## Enemy (`c`)

`type` is the behaviour class; `spawnCode` (from the level) picks the variant and
its stats. From `Enemy.update`:

| `type` | Spawn codes | Behaviour |
|---|---|---|
| 0 | 3..5 | charger: runs at the player, jumps ledges, and explodes (spawns projectile 21 and removes itself) when close |
| 1 | 0..2 | melee brawler: walks up, attacks on a cooldown with the attack box (`attackDamage`) |
| 2 | 6..13 | ranged patroller: turns every 1100 ms, fires via `attack()` |
| 3 | 14..25 (default) | turret: four mounts (`mount`), fires via `attack()` |
| 4 | 24 | harmless morphed critter: the class-6 weapon converts a kill into this and it is not counted (`countLiveEnemies`) |
| 5, 6, 7 | 27, 28, 26 | the three parts of the boss, linked through `Game`'s `P`/`Q`/`R` slots |

`state`: 0 idle, 1 walk, 2 jump, 3 attack, 4 hurt, 5 dead.
`animSequenceMap[type*10 + state]` picks the animation sequence.
